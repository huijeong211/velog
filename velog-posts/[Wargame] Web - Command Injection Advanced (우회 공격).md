<h2 id="📌-1-핵심-개념-요약">📌 1. 핵심 개념 요약</h2>
<p>주요 개념: 커맨드 인젝션(Command Injection) 방어 우회 기법</p>
<p>한 줄 요약: 서버의 단순한 금지 단어(블랙리스트) 기반 필터링을 리눅스 와일드카드 및 경로 조작을 통해 무력화하고 플래그를 획득함.</p>
<h2 id="🔍-2-문제">🔍 2. 문제</h2>
<p>개요: 웹 페이지의 입력창을 통해 사용자의 명령어를 백엔드 리눅스 서버 환경의 echo $({user_input}) 구조 안에서 실행하는 서비스가 주어짐.</p>
<p>목표: 서버 내부에 숨겨진 진짜 정답 파일인 flag.txt를 읽어야 하지만, 파이썬 소스코드단에서 flag라는 단어가 입력되면 무조건 실행을 차단(No!)하는 방어가 걸려있음.</p>
<h2 id="🚀-3-해결-과정">🚀 3. 해결 과정</h2>
<p>취약점 탐색 (로컬 테스트): 백엔드에서 사용자 입력을 검증하는 시점과 실제 리눅스 셸(Shell)이 명령어를 실행하는 시점의 '해석 차이'를 이용한 우회 취약점을 타겟으로 잡음.</p>
<p>1차 시도 (따옴표 및 특수문자 쪼개기): cat f'l'a'g'.txt, 세미콜론(;), 백틱(`) 등을 활용해 필터링을 피해 가려 했으나, 출제자가 특수문자나 괄호 구조(echo $())를 깐깐하게 통제하여 공백(Blank) 화면이나 구문 에러(Syntax Error)를 반환함.</p>
<p>2차 시도 (와일드카드 필살기): 특수문자를 전면 배제하고, 오직 알파벳과 리눅스 물음표 와일드카드(?)만 활용하여 cat ????.txt 명령어를 전송함. flag라는 단어를 쓰지 않았기 때문에 파이썬 방어벽을 완벽히 속임.</p>
<p>힌트 발견 (Where is Flag? ./dream/hack/hello): 명령어가 성공적으로 실행되어 기존 flag.txt를 읽었으나, 안에는 진짜 정답 대신 진짜 정답이 숨겨진 경로인 ./dream/hack/hello 주소가 적혀 있었음.</p>
<p>최종 플래그 획득: 정답 경로를 포함하되, 여전히 flag 단어 필터링은 피해야 하므로 물음표 와일드카드를 섞은 최종 페이로드 cat ./dream/hack/hello/????.txt를 주입하여 진짜 정답인 DH{...}를 성공적으로 탈취함.</p>
<h2 id="📝-4-오늘의-삽질--복기">📝 4. 오늘의 삽질 &amp; 복기</h2>
<p>어려웠던 점 / 막혔던 부분: 처음에는 단순히 따옴표를 찢거나 세미콜론으로 명령어를 강제 종료하면 끝날 줄 알았으나, 백엔드의 echo $() 괄호 구조와 특수문자 제약 때문에 화면에 아무것도 나오지 않거나 에러가 반복되어 삽질을 거듭함.</p>
<p>새로 알게 된 점: 금지 단어(블랙리스트) 몇 개 필터링하는 식의 보안은 리눅스 시스템의 유연한 명령어 해석 기능(와일드카드 ?, *) 앞에 완전히 무력화된다는 본질을 직접 깨달음.</p>
<p>보안 대책 기여: 이러한 취약점을 근본적으로 막기 위해서는 사용자의 입력값이 운영체제 명령어(Shell)의 인자로 직접 전달되는 구조 자체를 피해야 하며, 부득이한 경우 블랙리스트가 아닌 허용된 명령어만 실행 가능한 '화이트리스트' 방식으로 설계해야 함.</p>

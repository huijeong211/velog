<h2 id="📌-1-핵심-개념-요약">📌 1. 핵심 개념 요약</h2>
<p>주요 개념: SSH(Secure Shell) 원격 보안 접속 및 리눅스 파일 탐색/문자열 검색(grep)</p>
<p>한 줄 요약: 원격 리눅스 서버에 SSH로 안전하게 로그인한 후, 출제자가 숨겨놓은 가짜 미끼 플래그를 구별하고 리눅스 내부 파일 시스템 전체를 탐색하여 진짜 플래그를 획득함.</p>
<h2 id="🔍-2-문제">🔍 2. 문제</h2>
<p>개요: SSH(Secure Shell) 프로토콜을 이용해 원격 리눅스 서버 환경에 직접 로그인하여 시스템 내부를 탐색하는 실습 문제가 주어짐.</p>
<p>목표: 제공된 계정 정보(id: chall / pw: dhbgssh)와 할당된 포트를 이용해 서버에 정상적으로 접속한 뒤, 가상머신 내에 숨겨진 DH{...} 형식의 최종 플래그를 찾아내야 함.</p>
<h2 id="🚀-3-해결-과정">🚀 3. 해결 과정</h2>
<p>1단계: 윈도우 환경에서 SSH 기본 접속
윈도우 10/11 환경에는 OpenSSH 클라이언트가 기본 내장되어 있으므로 별도의 프로그램(PuTTY 등) 설치 없이 파워셸(PowerShell)을 이용해 다이렉트로 접속을 시도함.</p>
<p>최초 접속 시 호스트 신뢰 확인 문구에 yes를 입력하고, 보안상 화면에 노출되지 않는 비밀번호 dhbgssh를 정확히 타이핑하여 chall@가상머신이름:~$ 형태의 원격 리눅스 셸(Shell)을 획득함.</p>
<p>2단계: 가짜 플래그 낚시 분석 (1차 시도)
현재 폴더에서 파일 목록을 확인하고 플래그로 추정되는 파일을 찾아내어 내부 내용을 출력함.</p>
<p>그러나 파일 내부에는 DH{this_is_not_real}이라는 가짜 플래그 문자열만 유일하게 존재하고 있었음. 출제자가 공격자를 속이기 위해 가짜 미끼를 던져둔 것임을 파악하고 파일 시스템 전수 조사를 계획함.</p>
<p>3단계: 리눅스 전수 조사를 통한 진짜 플래그 획득 (최종 성공)
현재 위치한 홈 디렉토리 외에 숨겨진 파일(.flag 등)이 있거나 하위 경로에 진짜 정답이 있을 것으로 판단, 현재 폴더 및 하위 모든 경로의 파일 내용을 통째로 스캔하는 grep 치트키 명령어를 실행함.</p>
<p>표준 에러를 필터링하는 옵션을 주어 권한 거부 메시지를 배제하고, 진짜 정답 형식인 DH{ 문자열을 포함한 모든 파일 라인을 추적함. 그 결과 가짜 미끼 파일 외에 숨겨져 있던 진짜 파일의 경로와 최종 플래그(DH{...}) 데이터를 완벽하게 탈취하는 데 성공함.</p>
<h2 id="📝-4-오늘의-삽질--복기">📝 4. 오늘의 삽질 &amp; 복기</h2>
<p>어려웠던 점 / 막혔던 부분: SSH 접속 후 눈앞에 보이는 파일만 열었을 때 플래그 형식의 문자열이 바로 나와 정답인 줄 알고 좋아했으나, 페이크 파일임을 깨닫고 순간 당황했다. 리눅스 환경에서 다수의 낚시 파일이나 깊은 디렉토리 구조 속에 정답을 숨겨두었을 때 수동으로 일일이 찾아다니기에는 효율성이 극도로 떨어진다는 난관이 있었다.</p>
<p>새로 알게 된 점: nc와 달리 ssh 접속은 원격지의 리눅스 컴퓨터 내부 시스템으로 완전히 로그인하여 제어 권한을 얻는 개념임을 확실히 인지했다. 또한, 시스템 내부에 정답이 교묘하게 숨겨져 있을 때는 파일 내용 내부의 특정 패턴을 실시간으로 역추적하는 grep -r 명령어와 에러 리다이렉션(2&gt;/dev/null) 조합이 얼마나 강력한 파일 탐색 무기인지 직접 깨달았다.</p>
<p>보안 대책 기여: 시스템 해킹 실습 환경이 아닌 실제 상용 서버라면, 외부에서 SSH로 직접 접근할 수 있는 계정의 비밀번호를 본 문제처럼 단순하게 설정하거나 외부에 노출해서는 안 된다. 무차별 대입 공격(Brute Force)을 막기 위해 패스워드 인증을 비활성화하고 고유한 SSH 키 페어(Key Pair) 인증 방식을 강제해야 하며, SSH 기본 포트(22)를 변경하여 노출을 최소화해야 함을 복기했다.</p>

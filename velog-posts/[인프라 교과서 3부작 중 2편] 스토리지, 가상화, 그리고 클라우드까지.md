<h2 id="2-독서-목표-및-분석">2. 독서 목표 및 분석</h2>
<p>앞선 1편에서 온프레미스(물리 서버)의 구조와 하드웨어적 한계를 이해했다면, 이번 2편에서는 현대 IT 인프라의 꽃인 '가상화'와 '클라우드'를 다룬다. 그동안 워게임 실습을 하며 파편적으로 다루었던 도커(Docker) 컨테이너나, 최근 수강을 시작한 AWS(Amazon Web Services) 환경이 실제 인프라 역사에서 어떤 흐름으로 등장하게 되었는지 맥락을 파악하는 것이 이번 챕터의 목표이다.</p>
<h2 id="3-핵심-개념-요약">3. 핵심 개념 요약</h2>
<p>가장 흥미로웠던 점은, 책을 읽는 내내 내가 최근 개인적으로 진행해 온 실습들이 계속해서 오버랩되었다는 것이다.</p>
<p><strong>[6장: 서버 가상화] ➔ 드림핵(Dreamhack) 워게임 경험 매핑</strong></p>
<ul>
<li><p>책에서 호스트 OS 위에 논리적으로 분리된 환경을 구축하는 가상화 기술을 설명하는데, 예전에 드림핵 blue-whale 문제를 풀며 도커(Docker) 컨테이너의 레이어 구조와 Union File System을 뜯어봤던 기억이 났다.</p>
</li>
<li><p>그 당시 컨테이너 내부에서 민감 정보(비밀번호 등)를 rm으로 지워도 이전 레이어에 남아 복원될 수 있다는 것을 직접 실습했었는데, 책의 가상화 원리와 결합해 보니 왜 실무에서 멀티 스테이지 빌드(Multi-stage Build) 같은 철저한 이미지 관리가 필수적인지 명확히 이해가 되었다</p>
</li>
</ul>
<p><strong>[7장: 클라우드] ➔ AWS Cloud Essentials 교육 매핑</strong></p>
<ul>
<li><p>책의 7장에서 클라우드를 IaaS, PaaS, SaaS로 분류하고, 온프레미스 서버를 운영할 때와 클라우드를 이용할 때의 비용(회계 처리) 및 엔지니어의 역할을 비교한다.</p>
</li>
<li><p>이는 최근 내가 수강한 'AWS Cloud Essentials'에서 배운 '공동 책임 모델(Shared Responsibility Model)' 및 '온프레미스 직무의 클라우드 매핑' 개념과 완벽하게 일치했다. 하드웨어 패치나 데이터 센터 온도 관리는 AWS에 맡기고, 엔지니어는 아키텍처 설계와 논리적 보안(Security Group 등)에 집중해야 한다는 통찰을 책을 통해 다시 한번 확립할 수 있었다.</p>
</li>
</ul>
<h2 id="4-방향성에-대한-확신">4. 방향성에 대한 확신</h2>
<p>클라우드가 아무리 편리해도 결국 그 밑바탕은 물리적인 서버 인프라에 기반을 두고 있다. 서버 가상화와 클라우드 챕터를 읽으며, 현재 내가 수백 대 일의 웹/앱 개발 시장을 피해 OS, 네트워크, 클라우드, 보안이라는 컴퓨터공학 근본 지식을 파고드는 'DevSecOps' 타겟팅 전략이 완벽히 옳은 방향임을 느꼈다. 인프라 환경이 클라우드로 고도화될수록, 물리 장비의 제약을 코드로 통제하고 보안을 설계할 수 있는 깊이 있는 엔지니어의 수요는 기하급수적으로 늘어날 것이다.</p>

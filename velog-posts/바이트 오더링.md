<p>예시)</p>
<pre><code>#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;

int main(void) {
    char * str = &quot;ABCD&quot;; // 16진수: 41424344
    puts(str);    // 문자열 출력 결과: ABCD

    unsigned int num = 0;
    num = 0x41424344;
    printf(&quot;%x\n&quot;, num);  // 16진수 출력 결과: 41424344

    return 0;
}
</code></pre><h3 id="문자열-char">문자열 (char*)</h3>
<p>바이트 배열이다.</p>
<p>메모리 낮은 주소부터 순서대로 저장된다. (41 42 43 44)</p>
<h3 id="정수-unsigned-int">정수 (unsigned int)</h3>
<p>4바이트 크기의 단일 숫자 데이터다.</p>
<p>x86/x64 시스템(리틀 엔디안)에서는 하위 바이트부터 역순으로 저장된다. (44 43 42 41)</p>
<h2 id="1-문자열-abcd의-메모리-저장-방식">1. 문자열 &quot;ABCD&quot;의 메모리 저장 방식</h2>
<p>문자열은 각 문자가 1바이트 크기인 배열 형태로 메모리에 저장된다.</p>
<p>'A' = 0x41 (낮은 주소)</p>
<p>'B' = 0x42</p>
<p>'C' = 0x43</p>
<p>'D' = 0x44 (높은 주소)</p>
<p>puts(str)는 낮은 주소부터 높은 주소로 순서대로 1바이트씩 읽어 화면에 출력하므로 &quot;ABCD&quot;가 그대로 나온다.</p>
<h2 id="2-정수-0x41424344와-리틀-엔디안little-endian">2. 정수 0x41424344와 리틀 엔디안(Little Endian)</h2>
<p>대부분의 PC(x86, x64 아키텍처)는 리틀 엔디안 방식을 사용한다.</p>
<p>리틀 엔디안이란? 숫자의 하위 바이트(작은 단위)를 메모리의 낮은 주소에 저장하는 방식.</p>
<p>0x41424344라는 정수를 1바이트씩 쪼개보면 다음과 같다.</p>
<p>상위 바이트 (MSB): 0x41 (큰 단위)</p>
<p>하위 바이트 (LSB): 0x44 (작은 단위)</p>
<p>이를 메모리에 저장하면 바이트 순서가 뒤집힌다.</p>
<p>'A' = 0x44 (낮은 주소)</p>
<p>'B' = 0x43</p>
<p>'C' = 0x42</p>
<p>'D' = 0x41 (높은 주소)</p>
<h2 id="3-printfx-num은-41424344로-출력되는-이유">3. printf(&quot;%x&quot;, num);은 41424344로 출력되는 이유</h2>
<p>printf(&quot;%x&quot;, num)의 동작 방식:</p>
<ol>
<li><p>%x는 메모리 바이트를 하나씩 읽는 것이 아니라, CPU가 32비트 정수 전체를 하나의 값으로 읽어 들인다.</p>
</li>
<li><p>CPU가 리틀 엔디안 메모리에서 44 43 42 41을 읽을 때, 원래 수치인 0x41424344로 다시 조합한다.</p>
</li>
<li><p>printf는 이 정수 수치(0x41424344)를 사람에게 보여주기 위해 16진수 문자열 형태로 출력해 주는 것뿐이다.</p>
</li>
</ol>
<p>즉, 메모리를 읽은 후 CPU가 원래 정수 수치로 다시 재조합하여 출력한다.</p>

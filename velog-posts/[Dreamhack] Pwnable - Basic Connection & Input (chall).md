<p>1단계: 소스코드 분석
제공된 chall.c 소스코드의 핵심 로직을 분석
서버에 접속한 뒤 Dreamhack이라는 문자열을 정확히 입력해주면 strcmp 함수가 0을 반환하면서 플래그를 출력해 주는 명확한 구조임을 파악.</p>
<p>2단계: 환경적 난관 (접속 실패와 에러)
웹 브라우저 접속 시도: 문제 페이지에 적힌 주소(http://...:16417)를 브라우저에 입력했으나 하얀 화면만 뜨며 접속이 되지 않았습니다. 포트 정보를 다시 확인한 결과, 이 문제는 웹 서버가 아니라 내부 포트(31337/tcp)로 포워딩된 터미널 기반 시스템 해킹 문제임을 인지.</p>
<p>윈도우 명령어(CMD/PowerShell) 시도: 안내된 nc 명령어는 윈도우 환경에 기본 설치되어 있지 않아 실행불가. 이를 우회하기 위해 파워셸(PowerShell) 소켓 명령어를 사용했으나, 입력 대기 시간 지연(타임아웃) 및 윈도우 네트워크 소프트웨어 중단 예외 에러(IOException)가 발생하며 데이터 수신 도중 세션이 강제 종료.</p>
<p>3단계: 파이썬 익스플로잇(Exploit) 스크립트 작성 및 최종 성공
네트워크 버퍼 뒤틀림과 수동 입력의 딜레이 문제를 해결하기 위해, VS Code를 활용하여 원격 서버와 직접 통신하고 데이터를 주고받는 파이썬 소켓 자동화 스크립트를 작성해 실행.</p>
<h2 id="📝-4-오늘의-삽질--복기">📝 4. 오늘의 삽질 &amp; 복기</h2>
<p>어려웠던 점 / 막혔던 부분: 처음에 주소만 보고 무조건 웹 해킹 문제로 착각하여 브라우저 새로고침만 반복하며 크레딧과 시간을 낭비했다. 이후 nc 문제임을 깨달았으나, 윈도우 환경 특유의 명령어 부재와 파워셸의 스트림 읽기 예외 에러 때문에 텍스트 전송 타이밍이 맞지 않아서 곤란했다.</p>
<p>새로 알게 된 점: 시스템 해킹(Pwnable) 문제는 단순 브라우저 요청이 아니라 로컬에서 원격 서버의 소켓과 다이렉트로 데이터를 실시간 스트리밍해야 한다는 메커니즘을 알았다. 또한 타임아웃이나 명령어 제한이 심한 환경에서는 파이썬의 socket 라이브러리를 이용해 네트워크 공격 스크립트를 직접 자동화하여 타격하는 것이 가장 확실하고 강력한 무기라는 것을 배웠다.</p>
<p>보안 대책 기여: 해당 소스코드는 사용자의 입력 크기를 scanf(&quot;%9s&quot;, inp_str)로 제한하여 버퍼 오버플로우(BOF)를 방어하고 있다. 하지만 strcmp를 통한 단순 하드코딩된 문자열 비교 방식은 소스코드나 바이너리가 유출될 경우 이처럼 쉽게 인증이 우회되므로, 민감한 검증 로직은 안전한 암호화 알고리즘이나 일방향 해시 비교 방식을 적용해야 함을 복기했다.</p>
